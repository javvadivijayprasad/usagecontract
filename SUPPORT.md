# Support

Thanks for using **usagecontract**. Here is how to get help.

## Questions and usage help

- Read the [README](./README.md) for the API overview and the
  [Getting Started guide](./GETTING-STARTED.md) for a step-by-step walkthrough.
- Search the [existing issues](https://github.com/javvadivijayprasad/usagecontract/issues)
  — your question may already be answered.
- If it is not, open a [new issue](https://github.com/javvadivijayprasad/usagecontract/issues/new)
  with the `question` label. Include your Node version, the package version
  (`npm ls @vijaypjavvadi/usagecontract`), and a minimal snippet that shows what
  you are trying to do.

## Reporting a bug

Open an issue with the `bug` label and include:

- what you expected to happen and what actually happened;
- a minimal reproduction (spec + consumer snippet, or a failing test);
- the exact command you ran and its full output.

Reproductions that run with `node --test` are the fastest for us to act on.

## Requesting a feature

Open an issue with the `enhancement` label describing the use case first, then the
proposed API. See [ROADMAP.md](./ROADMAP.md) for what is already planned.

## Security issues

Please do **not** open a public issue for a suspected vulnerability. Email
jvijayprasad@gmail.com instead. See the security section of
[CONTRIBUTING.md](./CONTRIBUTING.md).

## Response expectations

This is a community-maintained open-source project. Maintainers respond on a
best-effort basis. Clear, reproducible reports get answered fastest.
